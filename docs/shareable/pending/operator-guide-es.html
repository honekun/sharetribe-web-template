Sección 01

Archivo Vintach — Guía para operadores

Esta guía cubre todo lo que un operador del marketplace necesita para administrar Archivo Vintach: configurar contenido mediante la Sharetribe Console, definir campos de publicación y categorías, importar publicaciones de forma masiva y entender la configuración de la aplicación. No se requieren conocimientos técnicos.

Sección 02

Toda la configuración del marketplace se administra desde la Sharetribe Console en flex-console.sharetribe.com. Las áreas principales que usarás:

Sección 04

3. Campos de publicación

Los campos de publicación son los atributos que los vendedores llenan al crear una publicación (color, talla, marca, etc.).

Importante — dónde vive cada campo: Archivo Vintach usa dos fuentes para los campos de publicación. La mayoría se administra en la Sharetribe Console, pero tres están definidos en el código de la aplicación y no se pueden editar en la Console.

CampoDónde viveQuién puede editarlo
colorCódigo de la app (src/config/configListing.js)Solo el equipo de desarrollo
all_sizesCódigo de la app (src/config/configListing.js)Solo el equipo de desarrollo
brandCódigo de la app (src/config/configListing.js)Solo el equipo de desarrollo
generoConsole → Build → Listing fieldsOperador
estadoConsole → Build → Listing fieldsOperador
estiloConsole → Build → Listing fieldsOperador

Cuando un campo con la misma clave existe tanto en la Console como en el código, gana la definición del código. Por eso, agregar color, all_sizes o brand en la Console no tiene efecto — la app ignora la versión de la Console y usa la del código. Para agregar, renombrar o quitar opciones de estos tres campos, pídele al equipo de desarrollo que actualice src/config/configListing.js.

Las secciones siguientes describen la configuración canónica. Para los tres campos solo de código, las tablas documentan lo que la app espera; no necesitas recrearlos en la Console.

Los campos administrados en la Console (Console → Build → Listing fields) tienen:

  • Key — el ID interno (no cambia una vez creado)
  • Schema type — enum (elegir uno) o multi_enum (elegir varios)
  • Scope — siempre public para campos buscables
  • Options — los valores que los vendedores pueden elegir

Después de crear los campos, ve a Console → Build → Listing types, abre tu tipo de publicación y agrega ahí los campos para que aparezcan en el formulario de publicación.

Sección 05

4. Secciones de la landing page

La landing page se construye en Console → Content → Pages → Landing Page. Cada sección que agregas crea un bloque visual en la página.

Cómo funcionan las secciones

Cada sección tiene:

  • Section Type — determina qué hace la sección (la "plantilla")
  • Section ID — un nombre único para esta sección en particular
  • Section Name — nombre visible opcional; también se usa para aplicar tokens de estilo visual (ver Sección 5 — Opciones de visualización)
  • Blocks — elementos individuales dentro de la sección (publicaciones, categorías, imágenes, etc.)
  • Block Name — lo usan las secciones personalizadas para pasar datos; también lleva tokens de visualización para estilos a nivel de bloque (ver Tokens de Nombre de bloque)

4.1 Hand-Picked Listing Carousel (avSelections)

Muestra un carrusel horizontal desplazable de publicaciones específicas que eliges manualmente.

Configuración:

  1. Agrega una sección. Pon Section Type en avSelections.
  2. Pon Section ID en av-selections o av-selections-[cualquier-nombre] (p. ej. av-selections-verano). Cada ID único es un carrusel independiente.
  3. Agrega un bloque por publicación. En cada bloque, pon Block Name con el UUID de la publicación.
    • Encuentra el UUID de una publicación en Console → Manage → Listings → abre la publicación → copia el ID de la URL.
  4. Opcionalmente agrega un Title, Description y Call to Action al encabezado de la sección.

Notas:

  • Solo aparecen las publicaciones publicadas. Los borradores y las publicaciones cerradas se omiten en silencio.
  • El orden de los bloques controla el orden de las publicaciones en el carrusel.
  • Puedes tener varias secciones av-selections-* en la misma página.

4.2 Category Card Carousel (avSelectedCats)

Muestra un carrusel horizontal de tarjetas de categoría. Cada tarjeta muestra una foto y el nombre de la categoría, y al hacer clic abre la página de búsqueda filtrada por esa categoría. No hay carga automática de datos — todo el contenido proviene de lo que ingreses en la Console.

Configuración:

  1. Pon Section Type en avSelectedCats.
  2. Pon Section ID en av-selected-cats o av-selected-cats-[nombre].
  3. Agrega un bloque por categoría:
    • Block Name — el ID de la categoría (p. ej. ropa, ropa-vestidos, bolsas, zapatos)
    • Title — nombre visible opcional. Si se omite, la app usa el nombre de la categoría de tu configuración de categorías.
    • Media — sube la foto que se muestra en la tarjeta.

Notas:

  • El ID de categoría en Block Name debe coincidir exactamente con el ID de tu configuración de categorías.
  • Las tarjetas enlazan a la página de búsqueda filtrada por esa categoría.

4.3 Tag or Category Filtered Carousel (avTagListings)

Muestra un carrusel de publicaciones obtenidas automáticamente por un filtro. El filtro se define en el Block Name del primer bloque.

Configuración:

  1. Pon Section Type en avTagListings.
  2. Pon Section ID en av-tag-listings-[nombre] (p. ej. av-tag-listings-hot).
  3. Agrega un bloque. Pon su Block Name usando uno de estos formatos:
Formato de Block NameQué obtiene
tag:hot-listPublicaciones etiquetadas con hot-list
cat:ropa-vestidosPublicaciones de la categoría ropa-vestidos
hot-listIgual que tag:hot-list (tag es el predeterminado)

Notas:

  • Muestra hasta 24 publicaciones publicadas.
  • Solo se usa el Block Name del primer bloque como filtro. Los bloques adicionales se ignoran.
  • Puedes tener varias secciones av-tag-listings-*, cada una con su propio filtro.

4.4 Recommended Listings Grid (avRecommendeds)

Muestra una cuadrícula de varias columnas con publicaciones elegidas a mano. Funciona igual que el carrusel pero se muestra como cuadrícula.

Configuración:

  1. Pon Section ID exactamente en av-recommendeds (es fijo — solo una por página).
  2. Pon Section Type en avRecommendeds.
  3. Agrega un bloque por publicación, poniendo Block Name con el UUID de la publicación.

4.5 User Profile Carousel (avSelectedUsers)

Muestra un carrusel horizontal de tarjetas de perfil de usuario. Útil para destacar vendedores o marcas aliadas.

Configuración:

  1. Pon Section Type en avSelectedUsers.
  2. Pon Section ID en av-selected-users o av-selected-users-[nombre].
  3. Agrega un bloque por usuario. Pon Block Name con el UUID del usuario.
    • Encuentra el UUID de un usuario en Console → Manage → Users → abre el usuario → copia el ID de la URL.

4.6 Instagram-Style Image Grid (avInstaGrid)

Muestra una cuadrícula de fotos responsiva a partir de imágenes que subes directamente en la Console. Ideal para galerías tipo lookbook o mood boards. No se carga ningún dato de publicaciones.

Configuración:

  1. Pon Section Type en avInstaGrid.
  2. Pon Section ID en av-insta-grid o av-insta-grid-[nombre].
  3. Agrega un bloque por imagen. Sube la imagen en el campo Media del bloque. El título y la descripción del bloque son superposiciones opcionales.

4.7 Hero Banner (Multi-Instance) (avHero2)

Un hero banner flexible: una imagen de fondo con título, descripción y hasta dos botones CTA. Admite un fondo opcional solo para móvil, un enlace opcional de toda la sección y estilos de botón por instancia. Puedes colocar varias instancias independientes de avHero2 en la misma página — cada una se identifica por su Section ID.

Cómo se muestra:

  • Un panel hero: imagen de fondo (full-bleed) con el título, la descripción y los botones superpuestos.
  • El nombre de la instancia es la parte del Section ID después de av-hero2- (p. ej. av-hero2-summer → summer). Todas las claves de traducción de abajo usan ese nombre: AVHero2.summer.cta1Text, etc.

Configuración (Console → Content → Pages → [página] → Add section):

  1. Pon Section Type en avHero2.
  2. Pon Section ID en av-hero2-[nombre-único] (p. ej. av-hero2-summer).
  3. Define la imagen de fondo de escritorio en los ajustes de appearance de la sección.
  4. Llena el Title y la Description en los campos de la sección.
  5. Agrega los botones y cualquier opción mediante las claves de traducción de la tabla de abajo (Console → Content → Translations).

Botones (CTAs): Cada botón aparece solo cuando se define su clave de texto.

  • Un botón usa AVHero2.<name>.cta1Text / cta2Text para su etiqueta y AVHero2.<name>.cta1Link / cta2Link para su destino (predeterminado /s).
  • En las páginas CMS (/p/...) puedes en su lugar llenar los campos integrados de Call to Action de la sección; las claves de traducción, cuando se definen, tienen prioridad. En la Landing page, los botones provienen solo de las claves de traducción.

Textos de traducción (Console → Content → Translations; reemplaza <name> con el sufijo del Section ID):

ClavePredeterminadoEfecto

AVHero2.<name>.cta1Link/sDestino del primer botón (se usa cuando cta1Text está definido).
AVHero2.<name>.cta1StylevacíoTokens de estilo del primer botón (ver abajo). Vacío → tokens CTA del Section Name, luego primary.
AVHero2.<name>.cta2TextvacíoEtiqueta del segundo botón. El botón solo se muestra cuando se define.

AVHero2.<name>.bgLinkvacíoConvierte toda la sección en un enlace a esta URL. Déjalo sin definir o en # para no enlazar.

Estilo de botones — dos formas:

  1. Por botón (traducción): cta1Style / cta2Style reciben tokens cortos separados por espacios. Combina un color con tokens de forma/fuente, p. ej. blue rounded o purple solid.
    • Color: primary, secondary, blue, lightBlue, purple, pink, yellow
    • Forma / borde: roundedFull, rounded, square, dashed, solid, noOutline
    • Fuente: headingFont, bodyFont, accentFont
  2. Ambos botones (Section Name): Si dejas cta1Style / cta2Style vacíos, cualquier token CTA en el Section Name aplica a ambos botones — p. ej. Section Name Summer Hero - SectionCtaBtnBlue - Rounded. Ver Opciones de visualización de sección para la lista completa de tokens. Cuando ninguno está definido, los botones usan los estilos predeterminados primary / secondary.

Tokens de visualización del Section Name: Además de los tokens CTA anteriores, esta sección respeta los tokens estándar del Section Name (color/alineación del título, paddings, etc. — ver Opciones de visualización de sección). El específico del hero es - ShortHero, que reduce la altura del hero.

4.9 Block-Based Hero (avHero3)

Un hero de dos paneles. Cada panel es una imagen de fondo full-bleed con un texto superpuesto y un botón opcional. Ideal para layouts divididos como "Mujer / Hombre" o "New In / Sale".

Cómo se muestra:

  • La sección usa sus primeros dos bloques como los dos paneles. Un solo bloque genera un panel de ancho completo; cualquier bloque más allá de los primeros dos se ignora.
  • Los paneles se colocan lado a lado en escritorio (≥768 px) y se apilan verticalmente en móvil (<768 px).
  • El título y la descripción de cada panel se superponen en blanco en la esquina inferior izquierda de la imagen. (La alineación del texto por bloque no es configurable por el operador.)

Configuración (Console → Content → Pages → [página] → Add section):

  1. Pon Section Type en avHero3.
  2. Pon Section ID en av-hero3-[nombre] (p. ej. av-hero3-shop). La parte después de av-hero3- (aquí, shop) es el nombre de la instancia usado por las claves de estilo opcionales de abajo.
  3. Agrega hasta dos bloques. Para cada bloque:
    • Block image (Media): sube la imagen de fondo del panel. Requerida para que el panel muestre una imagen.
    • Block title / Block text: texto superpuesto opcional.
    • Block image link (opcional): define el Link de la imagen del bloque para hacer que todo el panel sea clickeable — una ruta interna (p. ej. /s?pub_categoryLevel1=ropa) o una URL externa.
    • Call to action (opcional): agrega un botón con su propio texto y dirección de enlace Interno/Externo. Este enlace es independiente del Block image link.

Dos áreas clickeables, dos destinos: El Block image link hace que todo el panel sea un enlace; el botón de Call to action tiene su propio enlace separado. Pueden apuntar a lugares distintos. El botón se superpone sobre el enlace del panel, así que ambos funcionan y no hay enlaces anidados inválidos.

  • Un solo panel — agrega tokens al Block Name de ese bloque usando la sintaxis token :: (cada token termina con un espacio + ::). Esto sobrescribe el estilo a nivel de sección solo para ese panel. Ver Tokens de Nombre de bloque para la lista completa.
    • Color (elige uno): blockCtaBtnBlue, blockCtaBtnLightBlue, blockCtaBtnPurple, blockCtaBtnPink, blockCtaBtnYellow

8. Herramienta de importación masiva

8.1 Resumen

La herramienta de importación masiva te permite crear muchas publicaciones a la vez subiendo un solo archivo ZIP que contiene una hoja de cálculo CSV y todas las imágenes de las publicaciones. Está disponible en /admin/bulk-import en el marketplace.

Quién puede usarla. Cualquier usuario con sesión iniciada que pueda crear publicaciones puede usar la herramienta para crear publicaciones de forma masiva en su propia cuenta — cada publicación se crea bajo la persona que la sube. No hay contraseña de operador ni lista de acceso aparte. La pantalla de nueva publicación (/l/new) también muestra un botón azul "Bulk import" (en escritorio) que enlaza directo a la herramienta.

Los administradores (el pequeño conjunto de correos configurados en BULK_IMPORT_OPERATOR_EMAILS — ver Configuración de importación masiva) obtienen un poder extra: pueden agregar una columna user_id al CSV para crear publicaciones a nombre de otros vendedores. Para todos los demás esa columna se ignora y se rechaza.

Datos clave:

  • Cada fila del CSV crea una publicación; las filas se procesan una por una, así que si una falla las demás continúan.
  • Las publicaciones se crean bajo la cuenta de quien las sube por defecto (los administradores pueden sobrescribir por fila).
  • La herramienta es por niveles — los administradores pueden importar lotes más grandes que los vendedores normales: | Límite | Vendedor normal | Admin | | ------------------- | -------------- | ----- | | Publicaciones por importación | 25 | 100 | | Imágenes por ZIP | 100 | 400 | | Tamaño del archivo ZIP | 20 MB | 50 MB | | Importaciones por hora | 3 | 20 |
  • Solo puedes ejecutar una importación a la vez por cuenta, y el servidor ejecuta como máximo 3 importaciones simultáneas entre todos los usuarios — si está ocupado se te pedirá que lo intentes de nuevo en breve.

8.2 Cómo usarla

  1. Abre la herramienta — ve a [URL de tu marketplace]/admin/bulk-import, o haz clic en el botón azul "Bulk import" en la pantalla de nueva publicación. Solo necesitas tener sesión iniciada — no hay clave ni contraseña de importación que ingresar.
  2. Descarga la plantilla CSV — haz clic en "Download CSV Template" para obtener una hoja de cálculo prellenada con los encabezados de columna correctos (en español, p. ej. Nombre de Producto*, Precio Venta (MXN)*) más una fila de ejemplo. El enlace "Ver ejemplo de ZIP" en la barra de ayuda descarga un ZIP de ejemplo completo y listo para subir (un CSV más las imágenes correspondientes) que puedes abrir para ver exactamente cómo se ve una importación terminada.
  3. Llena el CSV — una fila por publicación, reemplazando la fila de ejemplo. Ver la Referencia de columnas CSV abajo. Deja la columna user_id vacía a menos que seas administrador importando para otro vendedor.
  4. Prepara tus imágenes — nombra cada archivo de imagen con claridad. Los nombres de imagen en el CSV deben coincidir exactamente con el nombre de archivo (incluida la extensión) de los archivos de imagen en tu ZIP. Las imágenes deben ser archivos reales .jpg, .png o .webp (la herramienta revisa el contenido real del archivo, no solo la extensión).
  5. Crea el ZIP — empaca tu CSV terminado y todos los archivos de imagen en un solo archivo .zip. Las imágenes pueden estar en subcarpetas.
  6. Sube e inicia — haz clic en "Select ZIP file", elige tu archivo, luego haz clic en "Start Import".
  7. Monitorea el progreso — la página muestra una barra de progreso en vivo e informa qué publicaciones se crearon correctamente y qué filas tuvieron errores. Mantén la página abierta; el progreso está ligado a tu cuenta, así que no puedes consultarlo desde otra cuenta.

8.3 Estructura del archivo ZIP

Tu ZIP debe contener exactamente un archivo CSV (en cualquier nivel dentro del archivo) y todas las imágenes referenciadas por ese CSV.

Ejemplo:

code
my-listings.zip
├── listings.csv
├── vestido-frente.jpg
├── vestido-trasera.jpg
└── photos/
    ├── jeans-frente.jpg
    └── jeans-detalle.jpg

Reglas del ZIP:

  • Exactamente un archivo CSV (cualquier nombre, cualquier nivel de carpeta)
  • Todas las imágenes referenciadas en el CSV deben estar presentes
  • Dos imágenes no pueden compartir el mismo nombre de archivo, ni siquiera en carpetas distintas
  • Las imágenes deben ser archivos .jpg, .png o .webp genuinos
  • Los límites de tamaño y cantidad dependen de tu nivel (ver la tabla en 8.1): vendedores normales hasta 25 publicaciones / 100 imágenes / 20 MB; administradores hasta 100 publicaciones / 400 imágenes / 50 MB

8.6 Qué se valida antes de iniciar la importación

Antes de crear una sola publicación, la herramienta ejecuta una verificación previa (pre-flight) estricta sobre todo tu ZIP y CSV. Si algo en esta verificación falla, la importación se rechaza de inmediato — no se inicia ningún trabajo, no se toca ninguna publicación — y obtienes de vuelta una lista de todos los problemas encontrados, para que puedas corregirlos todos de una sola pasada y volver a subir.

Esto es distinto de los errores por fila que puedes ver mientras una importación está corriendo. Una vez que la verificación previa pasa, las filas se crean una por una; si una fila individual falla en esa etapa (por ejemplo, un valor de color inválido), se reporta en la tabla de errores y las demás filas continúan. Las filas exitosas no se listan individualmente — cuando todas las filas se importan correctamente, la página muestra un botón Ver tus anuncios que abre tu página de anuncios (/listings). Ver Solución de problemas para esos casos.

La verificación previa se ejecuta en dos pasadas.

Pasada 1 — el archivo ZIP en sí

  • El archivo es un .zip válido y legible.
  • Contiene exactamente un archivo CSV (cualquier nombre, en cualquier nivel de carpeta).
  • El archivo CSV no está vacío.
  • Cada imagen es una imagen genuina — la herramienta lee el contenido real del archivo (magic bytes), así que un archivo que no es imagen renombrado a .jpg se rechaza. Tipos permitidos: .jpg/.jpeg, .png, .webp.
  • Dos imágenes no comparten el mismo nombre de archivo, ni siquiera en subcarpetas distintas.
  • El archivo se mantiene dentro de los límites de tu nivel: total de entradas, cantidad de imágenes, tamaño por imagen (10 MB), tamaño del CSV (5 MB) y tamaño total descomprimido.
  • La basura de macOS que Finder agrega al comprimir (__MACOSX/, los recursos ._* y los archivos .DS_Store) se ignora automáticamente — nunca causa un error.

Pasada 2 — el contenido del CSV

Esta es la verificación de "valores faltantes". Se ejecuta en dos etapas.

Verificaciones a nivel de archivo (detienen la importación de inmediato):

  • El CSV tiene al menos una fila de datos.
  • No tiene más filas que el tope de tu nivel (vendedores normales 25, administradores 100; aplica un techo absoluto de 100 para todos).
  • La fila de encabezados contiene las tres columnas obligatorias: title, price y description (los encabezados de la plantilla en español como Nombre de Producto* se reconocen y mapean automáticamente). Si falta por completo alguna columna obligatoria, la verificación se detiene aquí.

Verificaciones por fila (cada fila se revisa y todos los problemas se recopilan juntos):

Qué se revisaRegla que debe cumplir la fila
titleNo vacío.
descriptionNo vacío.
priceSe lee como un número positivo. Un signo $ y separadores de miles están bien; 0, negativos y texto no.
Columnas de imagen obligatoriasimage_front, image_back e image_horizontal tienen cada una un nombre de archivo. (image_details / imagen 4 es opcional.)
Nombres de archivo de imagenCada nombre de archivo referenciado en la fila existe en el ZIP. Un error de tipeo o una extensión incorrecta falla aquí.
Claves pub_*Una columna pub_*/pd_* no usa un nombre reservado (__proto__, constructor, prototype).
location_lat / location_lngSi están presentes, ambos son números válidos.
stockVacío toma 1 por defecto; de lo contrario debe ser un número entero igual o mayor que cero.
user_idSolo lo puede llenar un administrador. Un no-admin que lo defina recibe un error claro y la fila se rechaza.

Lo que no se revisa en esta etapa (importante):

  • Los valores de opción no se verifican contra la Console. Los valores de campos como color, talla, marca, categoría, género, estado, estilo y temporada se pasan tal cual. Un error de tipeo como pub_color = blu pasa la verificación previa y solo falla después, por fila, como un error de API en la tabla de errores. Usa siempre las claves de opción exactas de 8.5 Referencia rápida de valores de campo.
  • La existencia de la categoría también la confirma la API de Sharetribe durante el procesamiento, no aquí.

Qué ves cuando falla

Todos los problemas se devuelven juntos bajo el encabezado "Falta información para completar en tu archivo CSV. Completa la información en la plantilla y vuelve a exportar.", con una línea por problema. Los problemas específicos de una fila llevan el prefijo Fila N: (donde N es el número de fila de datos, empezando en 1). Por ejemplo:

code
Falta información para completar en tu archivo CSV. Completa la información en la plantilla y vuelve a exportar.
Fila 2: "title" está vacío.
Fila 2: "price" debe ser un número positivo, se recibió "abc".
Fila 5: "image_front" es obligatorio.
Fila 7: La imagen "vestido-frente.jpg" (image_front) no se encontró en los archivos subidos.

Corrige cada línea listada y vuelve a subir el ZIP.

10. Textos personalizados de traducción

Los textos personalizados de traducción controlan el texto editable por el operador en toda la app. Viven en dos lugares:

  • Archivos de traducción de la app (en_av.json / es_av.json) — los valores base que vienen con el código. Los actualiza el equipo de desarrollo.
  • Sharetribe Console → Content → Translations — sobrescrituras del operador. Los valores de la Console tienen prioridad sobre los archivos de la app.

Cómo actualizar un texto en la Console

  1. Ve a Console → Content → Translations.
  2. Usa el cuadro de búsqueda para encontrar la clave que quieres (p. ej. AVWelcomePopup.vendedor.title).
  3. Si la clave ya existe, haz clic en ella y edita el valor en el campo de texto, luego guarda.
  4. Si la clave aún no aparece (común para claves dinámicas por sección como AVHero2.my-section.mobileBackgroundUrl), haz clic en Add translation, ingresa la clave exactamente como se muestra en las tablas de abajo, escribe el valor y guarda.

Los cambios surten efecto en la siguiente carga de página. Una clave dejada en blanco o no agregada en absoluto hace que ese elemento se oculte en silencio — la app nunca muestra una clave en crudo a los usuarios.

Dos idiomas: Agrega la misma clave en las pestañas de inglés y español, o en cualquiera de los idiomas que admita tu marketplace.

Checkout — opciones de entrega y dirección de envío

El checkout (el paso que se muestra después de que el comprador hace clic en Comprar ahora) tiene estas partes específicas de AV:

  1. Formulario de dirección de envío — un layout de dirección solo para México: Nombre, Calle, Número Exterior / Número Interior, Colonia, C.P. / Ciudad, Estado (un desplegable de los 32 estados mexicanos) y Teléfono. El país siempre es México, así que no hay campo de país. La lista de estados está fija en el código.
  2. Opciones de entrega (cotización en vivo) — una vez que la dirección está completa, la plataforma solicita una cotización de envío en vivo al transportista (eShip) usando el tamaño de paquete de la publicación (S/M/L) y la dirección del comprador. El comprador entonces elige Express (la tarifa más rápida) o Estándar (la tarifa más barata); debajo de ellas, se listan todas las tarifas que devolvió el transportista por transparencia. Los precios para el comprador incluyen un margen sobre el costo base del transportista. Los precios no se fijan en la Console — provienen del transportista en tiempo real. El botón Pagar permanece deshabilitado hasta que se elige una opción de entrega.
  3. Sin cotización automática → Contactar AV — si el vendedor no ha definido una dirección de origen de envío, el artículo es de tamaño de paquete especial, o no se puede contactar al transportista, el comprador ve un botón de reintentar y/o un botón Contactar a AV en vez de opciones con precio (no puede completar una compra automática).

Requisito del vendedor: cada vendedor debe definir su dirección de origen de envío en Account → Dirección de origen (/account/shipping-origin). Sin ella, sus publicaciones no se pueden cotizar y los compradores ven Contactar a AV. Los vendedores que no la tengan reciben un banner recordatorio en Manage listings.

11. Favoritos (lista de deseos)

Los favoritos permiten a un comprador guardar los anuncios que le gustan y volver a verlos después desde una página personal. Funciona como una "lista de deseos" o "me gusta". No hay nada que configurar — está activo por defecto. Esta sección explica cómo se comporta para que puedas dar soporte a los usuarios y, si quieres, personalizar los textos.

Qué ve el comprador

  • Botón de corazón en cada tarjeta de anuncio. Un pequeño corazón aparece en la esquina superior derecha de cada tarjeta en todos los lugares donde se muestran tarjetas — resultados de búsqueda, los carruseles de la página de inicio, la Hot List, páginas de categoría y páginas de perfil. Al hacer clic se guarda (o se quita) el anuncio. Hacer clic en el corazón no abre el anuncio; solo alterna el favorito.
  • Botón de corazón en la página del anuncio. La página individual del anuncio muestra un corazón en la esquina superior derecha de la galería de fotos. Se mantiene sincronizado con el corazón de las tarjetas — marcar favorito en un lugar actualiza el otro.
  • La página de Favoritos (/favorites). Una página dedicada que lista todos los anuncios que el comprador ha marcado como favoritos, con la misma cuadrícula y estilo de tarjeta que los resultados de búsqueda, el favorito más reciente primero.

Cómo llega un comprador a la página de Favoritos

La página de favoritos está enlazada desde cuatro lugares (todos creados automáticamente):

UbicaciónCómo se ve
Barra superior (escritorio)Un icono de corazón negro, entre el sobre y el icono de la bolsa.
Menú de perfil (escritorio)Una entrada "Favoritos" en el menú desplegable del avatar.
Menú móvilUna entrada "Favoritos" en el menú móvil deslizable.
Barra lateral de la cuentaUna pestaña "Favoritos" junto a Mis Compras / Mis Ventas / Mi Balance.

Reglas y comportamiento

  • Requiere iniciar sesión. Los favoritos están ligados a una cuenta de usuario. Si un visitante sin sesión hace clic en un corazón, se le envía a la página de registro. No hay lista de favoritos "de invitado".
  • Privados para cada usuario. Los favoritos de un usuario solo son visibles para ese usuario. Los vendedores no pueden ver quién marcó sus anuncios como favoritos, y no hay un contador público de "me gusta" en los anuncios.
  • Límite de 100. Un comprador puede guardar hasta 100 favoritos. Al agregar el número 101 se elimina automáticamente el más antiguo.
  • Los anuncios eliminados o cerrados desaparecen. Si un anuncio favorito se elimina o se cierra después, simplemente deja de mostrarse en la página de favoritos — no se necesita ninguna acción del comprador ni del operador.
  • Nada que administrar para el operador. Los favoritos se guardan en el perfil de cada usuario. No aparecen en los datos de anuncios de la Console y no hay pantalla de administración para ellos.

Personalizar los textos

Todos los textos de favoritos se pueden cambiar en Console → Content → Translations (ver la Sección 1 para cómo funcionan las traducciones).

12. Bolsa de compras

La bolsa de compras permite a un comprador reunir anuncios que piensa comprar y pagarlos uno por uno. Funciona como un "carrito" / "lista para comprar". No hay nada que configurar — está activa por defecto. Esta sección explica cómo funciona para que puedas dar soporte a los compradores y, si quieres, personalizar los textos.

Bolsa vs. Favoritos: la bolsa es para artículos que el comprador planea comprar ahora (se paga desde ella); los favoritos/lista de deseos (Sección 11) son para artículos que quiere guardar para después. Son listas separadas.

Qué ve el comprador

  • Botón "Agregar a la bolsa" en la página del anuncio. En un anuncio de producto, debajo del botón "Comprar ahora", un botón de ancho completo Agregar a la bolsa añade el artículo a la bolsa. Una vez agregado dice En tu bolsa; al hacer clic de nuevo se quita.
  • Icono de bolsa en la barra superior. Un icono de bolsa (con un pequeño número que muestra cuántos artículos hay en la bolsa) se ubica entre el corazón de Favoritos y el sobre de la bandeja de entrada. Es visible para todos, incluidos los visitantes sin sesión. Al hacer clic se abre la página completa de la bolsa (/bag).
  • Desplegable de la bolsa (vista rápida). Al pasar el cursor sobre el icono de la bolsa (cuando tiene artículos), o al agregar un artículo, se abre un pequeño desplegable bajo el icono con el contenido de la bolsa. Cada fila muestra el vendedor, una miniatura, título, precio, talla, una acción Eliminar, un total por artículo y un botón de Comprar. Un enlace Ir a la bolsa abre la página completa. El desplegable se cierra al hacer clic fuera, presionar Escape o navegar a otra página.
  • La página de la Bolsa (/bag). Una página completa que lista cada artículo de la bolsa con las mismas tarjetas que el desplegable (vendedor, imagen, título, precio, talla, eliminar, total por artículo y comprar).

Reglas y comportamiento

  • Se guarda en el navegador, no en la cuenta. La bolsa se guarda en el navegador del propio visitante (almacenamiento local). Funciona sin iniciar sesión, pero no sigue al comprador entre dispositivos o navegadores, y borrar los datos del navegador la vacía. Es intencionalmente distinta de los favoritos, que se guardan en la cuenta.
  • Hasta 50 artículos, el más reciente primero. Al pasar de 50 se elimina el artículo más antiguo. Un anuncio solo puede estar una vez en la bolsa (es un marketplace de artículos únicos).
  • El pago es de un artículo a la vez. No hay un pedido combinado tipo "carrito" — cada transacción de Sharetribe es por un solo anuncio. "Comprar" en un artículo de la bolsa inicia el flujo normal de compra para ese artículo (cantidad 1). El envío se cotiza al pagar, así que la bolsa muestra la nota "Envío calculado al finalizar la compra" en lugar de un total de envío. El artículo permanece en la bolsa después de iniciar el pago (por si la compra se abandona); el comprador puede quitarlo manualmente.
  • Los anuncios vendidos o eliminados desaparecen solos. Si un anuncio de la bolsa se elimina o se cierra después, simplemente deja de aparecer — sin acción necesaria.
  • Nada que administrar para el operador. Las bolsas viven en el navegador de cada visitante; no aparecen en la Console y no hay pantalla de administración para ellas.
